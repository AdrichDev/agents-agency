# Validation: OpenClaw as the Brain

## User story
As Adrian (agency operator), I want to create and configure bots in the
agents-agency panel while OpenClaw executes them with the local LLM, so that I
manage everything from one UI, pay no per-token cloud cost for those bots, and
keep client data local.

## Acceptance criteria
- AC1 (F0): documented spike result — endpoint contract, auth, multi-agent
  support, provisioning API. Spec updated accordingly.
- AC2 (F1): an agent with `runtime="openclaw"` completes a chat conversation
  end-to-end through the agents-agency widget with responses generated by the
  local model (verified via Ollama logs / gateway logs), tools still working.
- AC3 (F1): agents with `runtime="openai"` behave exactly as before (regression
  suite green).
- AC4 (F2): creating an openclaw-runtime agent with a Telegram connection in the
  panel results in the bot answering on Telegram via OpenClaw, with the persona
  set in the panel, without any manual config in the OpenClaw stack.
- AC5 (F2): exactly ONE reply per incoming Telegram message (no double-reply);
  agents-agency webhook is NOT registered for openclaw-managed connections.
- AC6 (quality gate): eval set (≥10 scripted booking conversations) passes with
  0 invented slots/prices before any client-facing bot uses the local runtime.

## Scenario (Given-When-Then)
- **Given** an agent created in agents-agency with `runtime="openclaw"`, a persona,
  and a Telegram token connected
- **When** a client sends "¿qué horas tenéis libres el viernes?" to the Telegram bot
- **Then** exactly one reply arrives, generated by the local model via OpenClaw,
  listing only real slots from the business API, in the persona's voice.
